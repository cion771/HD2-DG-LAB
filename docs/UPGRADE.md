# 更新与回滚

HD2-DG-LAB 不会自动下载或覆盖程序。桌面中的“检查更新”只读取 GitHub Releases 版本与链接，所有更新和回滚都由用户确认后手动完成。

## 更新前

1. 在 Fluent 桌面版中停止检测，确认处于“已静音/未武装”。
2. 在 DG-LAB App 和设备端确认 A/B 输出均已停止，然后关闭桌面程序。
3. 备份本机应用数据目录中的配置。不要把配置、二维码、配对链接、日志或个人路径上传到 GitHub。
4. 记录当前桌面版本、桥版本与可正常工作的配置；不要只备份 EXE。

Fluent 桌面版的默认应用数据位于 `%LOCALAPPDATA%\hd2-DG-LAB\`；Lua 游戏桥的配置与日志位于 `%LOCALAPPDATA%\hd2coyote\`。不同历史版本可能使用其他位置，以实际配置位置为准。两个目录都只应保留在本机。

## 安装更新

1. 只从项目的 GitHub Releases 下载发布资产。
2. 对照 Release 中的 `SHA256SUMS.txt` 校验文件哈希。
3. 完全退出旧版后，将新 EXE 放到一个独立目录；首次先保留旧版文件，避免直接覆盖唯一副本。
4. 启动新版，先选择 Mock，检查安全边界、A/B 通道倍率和事件规则。
5. 按主页“启动检查向导”逐项确认。向导只读检查，绝不会自动武装。
6. 用 Mock 完成事件和急停测试，再连接真实设备。

## 是否需要更新游戏桥

Release 说明会明确标注桥协议或游戏布局是否改变：

- **仅桌面修复/界面功能**：通常只更换 EXE，不重新部署桥。
- **桥协议、游戏构建 profile 或 Lua 逻辑改变**：下载同一 Release 的桥 ZIP，通过受支持的 Mod 管理器导入、启用、Deploy，然后重启游戏。
- 在 Mock 且未武装状态下按 `safe → net → menu → recon → live` 验证。构建指纹不匹配时不要手填地址绕过。

不要混用不同 Release 的桌面程序、桥 ZIP 和 profile，除非发布说明明确声明兼容。

## 回滚

1. 停止检测、急停、确认设备输出归零并关闭新版。
2. 恢复上一版完整 EXE；若本次更新过桥，也恢复上一版对应桥 ZIP 并重启游戏。
3. 只有配置格式或行为出现问题时才恢复更新前的配置备份。新字段缺失时程序通常使用安全默认值，但不要假设所有跨大版本配置都兼容。
4. 先用 Mock 启动，检查安全边界和向导结果，再验证桥数据；不要以人体感觉判断回滚是否成功。

## 0.6.0 配置兼容性

从 0.5.9 更新到 0.6.0 时，旧配置可以继续读取：

- `detect.damage_merge_window_ms` 缺失时默认为 `250` ms；
- `safety.channel_a_multiplier` / `channel_b_multiplier` 缺失时均默认为 `1.0`；
- 新版首次保存设置后会写入这些字段；
- 0.5.9 回读新版配置时不会理解这些新字段，因此回滚前建议恢复旧配置备份。

## 发布验收

每个新版本应按 [发布验收矩阵](RELEASE_ACCEPTANCE.md) 执行。自动门禁验证源码、测试、隐私清单、构建资产和哈希；Windows、Mock、游戏桥、真机及回滚属于人工项。未执行的人工项必须明确标成 `PENDING`，不能因自动测试通过而宣称实机通过。

发布资产中的 `RELEASE-ACCEPTANCE.md` 是该版本的自动验收快照；人工项的环境与脱敏证据应记录在 Release 说明或独立验收记录中。

## 0.6.1 配置兼容性

0.6.1 不新增配置字段，与 0.6.0 配置格式兼容。更新仅增加发布验收工具、矩阵和随包文档；回滚到 0.6.0 不需要转换配置。

## 故障报告

报告问题时可提供程序版本、公开 Release 资产哈希、错误文本和已脱敏的复现步骤。不要提交真实二维码、局域网 IP、配对 URL、配置文件、日志原件、内存转储或包含用户名的绝对路径。
