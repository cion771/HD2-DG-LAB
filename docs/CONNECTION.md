# 桥连接排查（0.5.5）

## 自动读取玩家数据

安装 0.5.5 游戏桥，在桌面端游戏桥配置中选择 `live` 并保存，由用户重启游戏使配置生效。桌面端启用 `game_bridge` 并开始检测；验证时用 Mock、保持未武装。

`live` 会等待玩家出现，每 3 秒重试一次定位；有效数据按配置间隔上报，读取失败停止上报并自动重新定位。状态仅在变化时记录，避免逐帧写日志。桥心跳与玩家数据有效性仍分开判断。

这不是自动寻找未知偏移：必须已有正确的 profile。缺少血量偏移仍拒绝读取；偏移不匹配会继续报告原因，不能以假数据或任意地址代替。当前实机 profile 仍未验证。`menu` 依旧只验证通信，不会偷偷启用内存读取。


游戏桥到控制器是本机 UDP，不是需要粘贴的 Web 链接。手机 App 扫码连接是另一个独立通道。

1. 桌面端启用 `game_bridge` 事件源，点击“开始检测”。打开窗口或仅点“启动设备”不会监听游戏桥。验证时使用 Mock，保持未武装即可。
2. 控制器 UDP 监听端口与桥配置的 `port` 一致（默认 47777）。更改桥配置需要重启游戏。
3. 导入新版桥 ZIP 后由用户在 mod 管理器中 Deploy；不要按固定 patch 编号删文件，管理器可能重新编号。
4. 用 `menu` 模式先验证桥通信：不读取游戏玩家内存。0.5.4 的 menu/recon/live 使用已有帧回调每秒发心跳，因此桌面端晚启动也能重新发现桥。

## 状态含义

- **未监听游戏桥**：先启用 game_bridge 并开始检测。无需重新武装或连接真实设备。
- **等待桥心跳**：检查部署、桥日志、双方端口、帧钩子是否安装成功。旧版只在启动时发一次 hello，先开控制器再启动游戏可以验证这一点。
- **桥在线 · 数据未就绪**：UDP 通路可用，但没有新鲜玩家状态。menu 不读玩家状态；recon 是一次性侦察；live 定位失败也不会生成真实状态。详情显示桥当前模式与简短诊断。
- **游戏状态在线**：正在收到有效 state 包；仍需另外验证游戏字段含义正确，不能把传输成功当成偏移已验证。

safe 保持只写日志，不发心跳；net 保持一次性 hello 探测、不安装帧钩子。需要重复发现时使用 menu。旧版控制器/桥与新版搭配不保证完整显示模式和诊断，建议同时更新。

## 重要边界

心跳不产生伤害事件、不延长旧血量的有效期，也不读取游戏内存。定位失败（如“读不到 actor 数量”）是另一项尚未解决的游戏字段问题：不要随意填偏移、不要反复提高输出强度尝试解决。

日志、配置、内存报告、扫码 URL/二维码都可能包含私人信息。仅本地查看，不放入 GitHub、Release 或截图说明。离线测试须用临时目录，不能覆盖真实桥运行记录。
